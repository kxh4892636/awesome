## 表结构（与初稿的差异）

初稿是宽表 `(symbol, data_date, pe, pb, ps, dividend_yield)`，实现改成**长表**：

```sql
security_valuation(symbol, metric, trade_date, value, percentile, updated_at)
PRIMARY KEY(symbol, metric, trade_date)
```

理由：每个指标的值与分位独立到达，宽表要么用 NULL 占位（把「还没取到」和「算不出」混在一起），要么每加一个指标就迁移；长表里「有行」就等于「有这个观测」，取序列只多一个等值条件。代价是按指标多约 3 倍行数（930955.CSI 约 9.2k 行），SQLite 上可忽略。

## 实测（2026-11-16）

- 空库执行 `pnpm run sync:valuation`：930955.CSI 四指标各 2299 行，2017-05-26 → 2026-11-13；932315.CSI 各 571 行，2024-07-08 → 2026-11-13。
- 上游 2300 行、入库 2299 行：当日未收盘的数据按日线同一口径裁掉。
- 重复执行行数不变（总计 11480 行），upsert 幂等；事务按证券整批提交，重跑不破坏已有数据。
- 非 index 证券上游返回 `data:{}`，回填跳过并在摘要写 `skipped`（ETF 通道仍未接入）。
