# 001-确认估值数据源与指标口径

## 用户提供的数据源（2026-11-16）

`GET https://hongsehuojian.com/fundex-quote/index/valuation?securityCode=930955.CSI&valuationType=DID&timeInterval=max&ts=<毫秒时间戳>`，页面 `/red-rocket/indexDetail?securityCode=…`，样例响应在仓库根 `test.json`。用户确认 `valuationType` 取 `PE` / `PB` / `PS` / `DID`。

## 实测结论（2026-11-16）

| 项 | 结论 |
| --- | --- |
| 鉴权 | **匿名可用**：无 cookie、无 token、无 Referer 也返回 200 与完整数据；`pro`/`pla`/UA 可照抄但非必需。服务端定时同步无 token 过期问题 |
| 类型 | `PE`、`PB`、`PS`、`DID` 均可用；无效类型返回 `data:null`（HTTP 仍 200） |
| 单位 | PE/PB/PS 是倍数；DID 是百分数（4.4687 = 4.47%）。入库统一成比率，DID 除以 100 |
| 区间 | 只有 `timeInterval=max` 有数据，`10Y`/`5Y`/`1Y`/`all` 均返回 `data:null`；`ts` 被忽略 |
| 历史 | 930955.CSI 四项一致：2300 行，2017-05-26 → 当日，降序，只缺节假日；000300.SH 回溯至 2005 但仅 1124 行（稀疏，未深究） |
| 分位 | `data.percentile` 与 `items[].historicalPercentile` 为 0–99.95；`valuationQuantile = 100 − percentile`，文案用后者，**数值只取 percentile** |
| 空值 | `data:null`（未知代码/类型/非 max）与 `data:{}`（ETF 走 index 通道）都不能当 0；ETF 需另找通道，未接入 |
| 性能 | 单次 204–210 KB / 2300 行，常见 20–435 ms，冷启最慢 3.1 s；无 ETag/Last-Modified，只能自缓存；连续 20 次无 429 |
| 不可信字段 | `peg` 在 DID/PS 全 null、PE/PB 同值且可疑，不入库；`valuationQuantileNew*` 是中文字符串，不解析 |

## 契约（实现以 002/003 为准）

```ts
type ValuationMetric = "pe" | "pb" | "ps" | "dividendYield";
interface ValuationPoint { dataDate: string; value: number; percentile: number | null }
```

- 入库粒度：`(symbol, metric, trade_date)` 唯一，日频 upsert；每次取全量再 upsert（接口没有区间参数）。
- 顶层 `valuation` 与 `items[0].valuationValue` 一致，入库用 items，顶层只做一致性校验。
- 分位随历史增长而变，**存进每一行**，不事后重算。
