# 003-E2E单点失败连带后续旅程假红

## 适用条件与现象

`pnpm run test:e2e` 首轮出现「一红带两红」：先有一个旅程真失败（本例 S5 虚拟均线悬停），随后 S6/S7 报「数据加载失败」「证券列表为空」，看上去是产品坏了，其实与它们无关。

## 原因

`repos/etf/playwright.config.ts` 是 `workers: 1` + `fullyParallel: false`，所有 spec 串行跑在同一个 worker 里；S4（服务不可用再恢复）会在该 worker 内重启 18181 端口后端。Playwright 在某个 spec 失败后会丢弃 worker 并重启它，随之杀掉 S4 起的后端，后面使用同一端口的 spec 就再也没有可用服务。失败被传播成假红。

## 解决方法

按顺序修：只追**第一个**失败，后面的红先当噪声。

- 先单独跑那条 spec 确认它是真失败：`pnpm exec playwright test e2e/s5-virtual-ma.spec.ts`。
- 本次的真因是布局变化：估值卡片把 K 线画布推出了首屏，悬停坐标落空。修法是在取 `boundingBox()` 前 `await canvas.scrollIntoViewIfNeeded()`。
- 修完再整跑 `pnpm run test:e2e`，S6/S7 会自愈；若仍红，才按各自的错误信息继续查。

## 验证

2026-11-16 实测：首轮 3 红（S5/S6/S7），只补 S5 的一行 `scrollIntoViewIfNeeded()` 后重跑 7 组全绿（25.6s）；另起进程再跑一次仍全绿（26.8s）。
