# 002-估值数据接入

## 触发条件

- 首次部署、数据库为空，需要预填各证券的估值历史。
- 估值接口返回 1002 / 空序列，怀疑缓存缺失或上游口径变了。
- 需要核对某只证券的估值行数与起止日期、单位（倍数 vs 比率）、分位含义。
- 新增证券或上游历史窗口变化后，需要重建该证券的估值缓存。

日常最新估值由看板查询按需刷新（见「接口」一节），不必每次跑回填。

## 前提条件

- 网络可访问 `https://hongsehuojian.com`；该接口**匿名可调**，不需要 cookie / token / Referer（2026-11-16 实测无鉴权头也返回 200 与完整数据）。
- 在 `repos/etf` 目录执行；`DATABASE_DSN`（或 `.env`）指向目标 SQLite，未设置时默认 `./data/etf.sqlite`。
- 数据库迁移 0002 已应用（`openSqliteDatabase` 自动迁移，`security_valuation` 由 `migrations/0002_true_mister_fear.sql` 创建）。
- 回填是幂等 upsert，不删除旧观测；仍建议确认目标数据库。

## 取数

请求（代码见 `server/libs/hongsehuojian/valuation.ts`）：

```text
GET https://hongsehuojian.com/fundex-quote/index/valuation
  ?securityCode=930955.CSI      # 带交易所后缀的指数代码
  &valuationType=PE             # PE | PB | PS | DID
  &timeInterval=max             # 唯一的有效值
  &ts=<毫秒时间戳>              # 上游忽略，仅防缓存
Header: accept: application/json
```

| 项 | 实测结论（2026-11-16） |
| --- | --- |
| 类型映射 | `PE`/`PB`/`PS`/`DID` 四个上游类型，代码内部指标名为 `pe`/`pb`/`ps`/`dividendYield`，DID 就是股息率 |
| 鉴权 | 匿名可取；服务端定时同步没有 token 过期问题 |
| 区间 | **只有 `timeInterval=max` 有数据**。`5Y` 等返回 `data:null`，接口没有区间参数，因此每次都拉全量再 upsert |
| 单位 | PE/PB/PS 是倍数，原样入库；`DID` 是**百分数**（`4.4687` 即 4.47%），入库除以 100 统一成比率（`0.044687`） |
| 空数据 | `data:null`（未知代码、无效类型、非 max 区间）与 `data:{}`（ETF 走 index 通道）都表示无数据，解析为空数组，不能当 0 |
| 排序 | 上游按 `tradeDate`（`yyyyMMdd`）**降序**返回，`items[0]` 是最新一天；解析时转 ISO 并重排成升序，入库前的口径裁剪见下节 |
| 分位 | `items[].historicalPercentile` 为 0–99.95 的成立以来分位；顶层 `percentile` 与 `items[0]`（最新一天）同源，只有在 items 缺分位时用它补最新一行 |
| 响应体积 | 单指标约 204–209 KB（PE 209355 / PB 209167 / PS 204245 / DID 204266 字节，各 2300 行）；四指标一次刷新约 820 KB 上游流量 |
| 超时与错误 | 默认 15 s；超时映射 `deadline_exceeded`，其余上游失败映射 `upstream_unavailable` |
| 缓存头 | 无 `ETag` / `Last-Modified`，`ts` 也被忽略，只能靠本地缓存避免重复请求 |

分位文案与数值：界面文案「高于历史 X% 时间」用的是 `100 − percentile`，**数值只取 `percentile`**，不要反推。

## 入库

长表 `security_valuation`（迁移 0002）：

```sql
symbol text NOT NULL, metric text NOT NULL, trade_date text NOT NULL,
value real NOT NULL, percentile real, updated_at text NOT NULL,
PRIMARY KEY(symbol, metric, trade_date)
```

- 有行 = 有这个观测。取序列只多一个 `metric` 等值条件，不需要宽表的 NULL 占位。
- 幂等：`saveValuations` 在一个事务里整批 upsert，冲突时更新 `value` / `percentile` / `updated_at`；重跑行数不变。
- 口径日期：写入前裁剪到「上海昨日起的最近工作日」（`expectedValuationDate`），上游当日未收盘的那行不入库 —— 2026-11-17 实测上游含当日一行，库里最新停在 2026-11-16。
- 发布频率由上游决定：多数指数日频，`399989.SZ` 只有周频（2014-10-31 起 628 行，约 52 行/年，周五居多），同一只证券四项指标行数与日期范围一致。
- 逐证券串行、单证券内四指标并发（`Promise.all`）；证券变多时需要节流。
- 分位随历史增长而变，因此**逐行存分位**，不事后重算；每次刷新整批 upsert 都会用「当下全历史」重写历史行，实测一天内 2300 行里 1768 行漂移 0.02–0.03pp。要把某天的分位当不可变事实（回测、审计）得另加版本或快照。

## 回填

```sh
cd repos/etf && pnpm run sync:valuation
```

等价于 `node --experimental-strip-types server/sync-valuation.ts`：遍历证券目录（或 `symbols` 选项限定的子集），对每只证券并发拉四个指标，整批 upsert，最后打印 JSON 摘要（每指标 `rows` / `earliestDataDate` / `latestDataDate`，从库里读回）。上游无数据的证券写 `skipped` 且不写库。

## 接口

`GET /api/valuations?symbol=<带后缀代码>` → `ApiResponse<ValuationsResponse>`

- `data.series` 恒含 `pe`/`pb`/`ps`/`dividendYield` 四项且顺序固定，每项 `{ metric, points, latest }`；点形如 `{ dataDate, value, percentile }`。
- 缺数据用空数组表达（`points: []`、`latest: null`），不补 0。
- 刷新策略与日线一致：缓存最新日期早于应有工作日时，拉四个类型 upsert 一次；同一证券 10 分钟内只补拉一次（`REFRESH_COOLDOWN_MS = 10 * 60_000`，失败不记冷却），避免节假日或窗口重新聚焦时反复重下四份全历史；上游失败但已有缓存则退回缓存，没有缓存才报 1005 / 1006。
- 四指标全空（如 ETF 走 index 通道）→ 1002；目录外代码 → 1002「证券不存在」；缺 `symbol` → 1001。
- 响应是四指标全历史一次返回，单只证券约 **561694 字节**。暂无区间参数，前端按曲线范围自行截断。

验证（服务已在 8080 运行）：

```powershell
(Invoke-WebRequest 'http://127.0.0.1:8080/api/valuations?symbol=930955.CSI').RawContentLength   # 561694
Invoke-WebRequest 'http://127.0.0.1:8080/api/valuations?symbol=930955.CSI' | Select-Object -Expand Content | % { $_.Substring(0,600) }
```

```sh
curl -s "http://127.0.0.1:8080/api/valuations?symbol=930955.CSI" | head -c 600
```

应返回 `code=0`，`pe.points[0].dataDate` 为 `2017-05-26`，末行 `2026-11-13`。库里对账：

## 已知坑

1. **区间参数不存在**：`timeInterval=5Y` 返回 `data:null`。想要更短的历史只能拉全量在本地裁剪，别指望上游给区间。
2. **`data:{}` 不是空值而是「走错通道」**：ETF 代码（如 `515070.SH`）在 index 通道返回空对象，回填写 `skipped`；不换源、不估算。
3. **DID 差 100 倍**：上游给百分数，库里和接口给比率。混存会让股息率显示成 447%。
4. **分位别用 100 − percentile**：`100 − percentile` 只是上游文案的表述方式，数值必须取 `percentile`。
5. **响应大且不可增量**：四指标全历史约 561 KB 一次返回，证券多时接口与刷新成本线性增长；真要提速就补区间参数或节流，形状不变。
6. **缓存落后会重复打上游**：与日线同策略——查询发现缓存落后就再拉四次上游。

   > 纠正（2026-11-18，seq 1371..1516）：2026-11-17 CR 后已加同证券 10 分钟补拉冷却（`valuation-service.ts` 的 `REFRESH_COOLDOWN_MS`），失败不记冷却，「每次请求都重下」不再成立。冷却只存在单进程内存里，冷启动后首次仍会全量补拉；证券继续增多时还要考虑并发上限。

   > 补充（2026-11-23，seq 1141..1157、1287..1347）：冷却标记在补拉**完成后**才写入，同一时刻并发的多个「首次」请求仍会各自拉一轮四份全历史（一次约 820 KB 上游流量、约 9 千行 upsert）。要硬保证只能按证券做 in-flight 去重（共用同一个 Promise）。
7. **「应有最新日」按工作日推**：节假日不会报错，只是会多打一次上游；无害但会放大第 6 条的流量。
8. **上游杂字段不可信**：`peg`（DID/PS 全 null、PE/PB 同值）、`valuationQuantileNew*`（中文字符串）都不解析、不入库。
9. **当日行必须裁掉**：上游多一行当天未完成的观测，不裁会让「口径日期」与分位跳动。
10. **分位只有两位小数且分辨力更低**：上游给两位小数，实际步长约 `100 ÷ 历史点数`（2300 点约 0.04pp，570 点约 0.18pp），第二位小数是舍入噪声，别当测量精度；界面读数取整、悬停提示保留两位。

## 失败处理

- `not_found` / 1002：确认代码在证券目录内且带交易所后缀（`.CSI` / `.SH` / `.SZ`）。
- `upstream_unavailable` / 1005、`deadline_exceeded` / 1006：检查网络与上游可用性；事务未提交时直接重跑。
- `SQLITE_BUSY`：停掉本地 dev 服务或等当前写入结束；WAL 下通常可直接并发。
- 行数少于上游：先确认是否被上海昨日的口径裁剪（差 1 行属正常）。
