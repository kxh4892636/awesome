# 003-新增证券接入

## 触发条件

- 用户从上游抄来新的指数或 ETF，要求加进看板并爬数据。
- 顺手排除：调整既有证券的顺序不在此列——顺序就是默认标的，属行为变更（[ADR 008](../../adr/008-证券列表按目录加入顺序.md)）。

## 前提条件

- 拿到带交易所后缀的代码：`.CSI` / `.SZ` / `.SH`；两个通道都接受 `.SZ`（2026-11-17 实测 `399989.SZ` 日线与估值都可用）。
- 在 `repos/etf` 执行；网络可访问 `https://hongsehuojian.com`（匿名，不需要 token）。

## 步骤

1. **探测上游**。日线与估值的起点不同步是常态，两处都要看：
   - 日线：`createRemoteFetcher()(symbol, "qfq")` 按 `count=-10000` 拉全量，读第一根的 `tradeDate` 作为真实最早日。
   - 估值：`/fundex-quote/index/valuation?securityCode=…&valuationType=PE&timeInterval=max`，看 `items` 长度与首末日期；四项指标行数应一致。
2. **改目录**：只在 `server/market/repository/securities.ts` 的 `supportedSecurities` 追加一条，填上一步的日线最早日（不是估值起点），`assetType:"index"`、`currency:"CNY"`、`source:"hongsehuojian"`。**追加在末尾**，不重排既有项。
3. **入库**：不需要迁移。`createSqliteMarketRepository` 每次构造都按 `symbol` 幂等 upsert seed（`onConflictDoUpdate`），老库自动多出新证券。
4. **同步**：`pnpm run sync:market` 再 `pnpm run sync:valuation`；命令、裁剪口径与对账查询见 [001](../001-行情全量同步/001-行情全量同步.md) 与 [002](../002-估值数据接入/002-估值数据接入.md)。
5. **验接口**：`/api/securities` 顺序与目录一致；新代码的 `/api/daily-bars?symbol=` 与 `/api/valuations?symbol=` 都有数据，`meta.rows` 与库内计数对账。
6. **修测试与文档**：仓储测试断言完整顺序与首项（只断行数会漏掉排序回归）；README 与 [CONTEXT](../../CONTEXT.md) 里「证券数、日线/估值行数、目录顺序」这类事实同步改。

## 坑

1. **默认标的会静默变化**：任何「按代码排序」的实现都会把新代码插到前面。顺序取目录声明顺序，见 [ADR 008](../../adr/008-证券列表按目录加入顺序.md)。
2. **首次同步可能撞 15 s 超时**：报 `deadline_exceeded`，且错误对象不含证券代码，定位不到是哪一只；原样重跑通常就成功，先别动超时值与业务逻辑（2026-11-17 实测）。
3. **估值起点常晚于日线起点**：`932422.CSI` 日线 2013-12-31 起、估值 2024-12-31 起。`earliestTradeDate` 按日线写，否则全量同步会去请求一段上游没有的历史。
4. **个别指数估值是周频**：`399989.SZ` 628 行跨 12 年，分位按周频历史算，本地不插值、不重算。
5. **E2E fixture 只覆盖原有证券**：新证券在旅程里走 `skipped`，不影响用例；只要默认标的仍是红利低波100，S1/S6/S7 的断言不用改。

## 验收

2026-11-17 实测（目录 2→5）：日线 5×1665–5312 根（合计 18304）、估值每只 395–2300 行/指标（合计 20876，`trading_calendar` 11154 行含新增 `SZ` 交易所）；`/api/securities` 五只顺序正确，三个新代码的 `daily-bars` 与 `valuations` 与库内对账一致；`pnpm test` 223 例、两套 tsc、`typecheck:e2e`、`test:e2e` 7 组全绿。
