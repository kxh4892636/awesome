# 003-同步知识笔记的Anki卡片

适用：`docs/020-计算机` 里新增、删除、改名、合并或拆分笔记，或换了目录层级之后，让本机 Anki 与仓内笔记一致。制卡规则的规则源是 `repos/dsh-toolkit/src/nano-flow/skills/learning/ANKI.md`，AnkiConnect 侧能力走 `nnf anki`（见 nano-flow 域的 CLI 与 Anki 词条）；本文只写 wiki 这一侧的具体映射与验收。

## 映射（2026-11-24 现状）

| 项 | 规则 |
| --- | --- |
| 覆盖 | `020-计算机` 全树笔记，跳过每级目录的 `README.md` 与 `anki: false` 的笔记 |
| 根牌组 | `kxh::020-计算机` |
| 叶子牌组 | `kxh::020-计算机::<相对目录>`，每级用 `::` 拼、ASCII 段转小写；牌组粒度 = 目录（2026-11-23 起，见 [016](../../plans/active/2026-11-21-八股文转知识笔记/016-工程化目录平铺.md)） |
| 正面 | `<目录名去编号>-<文件名去编号>-<笔记 H1>` |
| 背面 | `<a href="https://wiki.kongxiaohan.cn/<uuid>">跳转wiki</a>`，`<uuid>` 取 front matter `id` |
| 一张几卡 | 一篇笔记一张 |

按目录数：应然 10 个叶子牌组、126 篇笔记（2026-11-24 口径，`030-工程化` 与 `040-系统设计` 都已平铺）。2026-11-24 实测仍是 15 个叶子牌组：`040-系统设计` 的 45 张卡还在六个旧子牌组（4 / 17 / 11 / 3 / 3 / 7）、父牌组 0 张，缺一次 `changeDeck` 合并与空牌组删除。目录平铺会合并牌组，新增子目录会多一层牌组。

## 步骤

1. **改笔记者先跑构建**：`pnpm --filter @kxh4892636/wiki build`。删过目录却没修上级 `README.md` 的链接会在这里就挂（`onBrokenLinks: throw`），比 Anki 更早暴露。
2. **列差异**：扫全树取每篇的 `id` 与首个 H1，生成候选；与 `deck:kxh*` 现有卡按背面 UUID 比对，分成「新增 / 内容待更新 / 换牌组 / 孤儿（磁盘已无此 UUID）」四类。UUID 是全站唯一键，用它对，别用正面文本。
3. **写增量**：新增卡导入、孤儿卡 `deleteNotes`、换牌组 `changeDeck`；正面因目录名、文件名或 H1 变化而过时的，一并更新。
4. **收牌组**：新目录建牌组；清空后的旧叶子牌组 `deleteDecks(cardsToo: true)` 删掉，空壳牌组会一直留在侧栏。
5. **复验**：`deck:kxh*` 总数 = 全树 `anki: true` 笔记数；每个叶子牌组张数 = 该目录笔记数；每条背面 UUID 与某篇 `id` 一一对应。

## 已知坑

- **牌组路径就是目录路径**：目录改名或平铺后不重命名牌组，同一批卡片会分裂成新旧两个牌组，复习计划跟着断。
- **正面含路径信息**：合并、拆篇、改 H1 之后只改内容不改正面，复习时看到的还是旧路径。
- **删笔记目录 = 两张账**：仓里要修 `README.md`（构建会挡），Anki 要删孤儿卡与空牌组。2026-11-23 删 `050-客户端/020-Vue` 时两件都做了，漏一件就出现「卡比笔记多」或构建红。
- **直连 AnkiConnect 的老坑**（2026-11-23 那轮用 `.temp/anki-*.py` 手搓时踩的）：参数必须嵌在 `params` 里，顶层传 `modelName` 报 `missing 1 required positional argument`，也会被误读成「0 张卡」；`deleteDecks` 即使牌组已空也必须 `cardsToo: true`；`dupe:front` 在该构建要求整数、用不了，去重只能按 UUID 自己做。改走 `nnf anki` 后这些不再直接面向调用方。
