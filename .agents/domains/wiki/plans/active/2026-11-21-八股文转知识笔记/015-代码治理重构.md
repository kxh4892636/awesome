# 代码治理重构

## 交付单元

用户要求把 `050-代码治理/001-ESLint原理.md` 从单工具原理扩成代码治理的抽象梳理，再介绍常用技术栈（eslint / prettier / biome / oxlint / oxfmt / commitlint / husky 等）。

## 四层抽象（三篇共用的边界）

| 层 | 解决什么 | 输入 → 输出 | 可自动修 | 典型落点 |
| --- | --- | --- | --- | --- |
| 规则检查 lint | 语义缺陷与团队约定 | 源码 + 配置 → 问题列表 | 部分 | pre-commit、CI |
| 格式化 format | 纯排版风格 | 源码 → 重排后的源码 | 全部且幂等 | 编辑器保存、pre-commit |
| 提交信息 commit message | 机器可解析的变更说明 | 消息文本 → 通过/拒绝 | 否 | commit-msg 钩子、CI |
| Git 钩子 hook | 把上面三层卡在本地 | 事件 → 执行命令 | — | core.hooksPath |

## 参考命令面（Vite+）

用户指定参考 <https://viteplus.dev/guide/>。Vite+ = Vite + Vitest + Oxlint + Oxfmt + Rolldown + tsdown + tsrs，全局 CLI 为 `vp`；三篇笔记要把命令当实证，不当结论。

| 层 | Vite+ 命令 | 事实要点 |
| --- | --- | --- |
| 检查 + 格式化 | `vp check` | Oxfmt 排版、Oxlint 查规则、tsrs 查类型；格式化先失败就停；`--fix` / `--fix-dangerously` / `--deny-warnings` / `--no-fmt` / `--no-lint` |
| 单跑 | `vp lint` / `vp fmt` | 单独跑 lint 或格式化 |
| 暂存检查 | `vp staged` | 内置 lint-staged 17，规则在 `vite.config.ts` 的 `staged` 块 |
| 钩子 | `vp hooks enable/disable/status`、`vp config` | dispatcher 装 `.vite-hooks/_` 并设 `core.hooksPath`；`VP_GIT_HOOKS=0` 可关 |
| 提交信息 | 无 | 官方命令面不校验 commit message，仍需 commitlint 或自写 commit-msg |
