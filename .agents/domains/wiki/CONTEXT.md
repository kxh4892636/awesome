# Wiki

`repos/wiki` 是个人知识站点：Docusaurus 直接把 `docs/` 下的 markdown 发布成站内文档，`sidebars.ts` 用 autogenerated，**目录结构与文件名就是站内结构**。内容按一级编号目录分栏目，编号决定侧栏顺序。

## Language

**栏目**：
`docs/` 下的一级编号目录（`000-中转`、`010-记录`、`020-八股文梳理`、`020-计算机`、`070-工作`、`090-归档`…），编号决定排序。每个栏目与 `020-计算机` 的每级目录都自带 `README.md` 落地页（2026-11-21 补齐，只列链接不写描述，见 [ADR 008](adr/008-知识笔记目录对齐归档编号.md)）；`docs/README.md` 是栏目索引，只列会被发布的栏目。
`docs/` 下进 git 的 markdown 全部会被发布，所以草稿、模板、占位内容只能放 `000-中转`（被 `.gitignore` 的 `*/*中转*` 挡在仓外）或仓外；`010-记录`、`070-工作` 同理是本机私有栏目，不进仓但本地构建照样渲染——要进仓的正文别放这三处。
_Avoid_：分区、频道

**八股文梳理**：
`020-八股文梳理` 栏目，内容取自 osjobs Top K 面试题统计：面经高频题按知识 tag 归档，一个 tag 一个文件。
站点的「试题总数 1736」是「题目 × 公司」行数，唯一题目是 **849**；两个数字不要混用。
2026-11-18 起，已迁进知识笔记的题从这里删掉（`Golang.md` 整篇删除、`前端.md` 118 → 111）；2026-11-21 把前端 / 操作系统 / 数据库 / 系统设计 / 网络协议五个 tag 迁完，只剩 `算法.md` 与 `非技术.md` 两个文件；题数、行数与快照差见 [workflow 002](workflows/002-刷新八股文题目快照/002-刷新八股文题目快照.md)「现状」表，重抓与重生成也照它走。
_Avoid_：题库、面经集合

**知识笔记**：
`020-计算机` 栏目下「一个问题一篇」的文档：H1 就是问题，第一条 H2 固定是「常见问题」（直接抄八股原文），之后是概念索引与逐个概念的正文。二级目录对齐 `090-归档` 的编号（见 [ADR 008](adr/008-知识笔记目录对齐归档编号.md)）：`010-理论基础/{030-计算机网络,040-设计模式,050-计算机系统}`、`020-编程语言/{010-HTML,020-CSS,030-JavaScript,040-Go}`、`030-工程化`（平铺，无二级目录）、`040-系统设计/{001-网络与基础设施,002-存储与建模,003-分布式数据,004-架构与通信,006-可靠性与安全,007-设计与案例}`、`050-客户端/010-React`；浏览器渲染与缓存不再单开子目录，平铺在 `030-计算机网络` 末尾。编号按「同一知识边界相邻」排：TCP 一组、UDP 一组、HTTP 一组、浏览器一组。
写法规则不在本域：由 dsh-toolkit 的 learning skill 维护（`repos/dsh-toolkit/src/nano-flow/skills/learning/NOTE.md`），这里只认它是什么、放在哪。
每篇一张 Anki 卡，牌组跟目录走；增删改名、合并拆分或改 H1 之后要同步，见 [workflow 003](workflows/003-同步知识笔记的Anki卡片/003-同步知识笔记的Anki卡片.md)。
用户手改过的笔记以用户稿为准：不「补全」、不重排、不把删掉的小节加回来，要动先问。
_Avoid_：学习笔记、knowledge note

**tag**：
站点 `api/category.json` 里的 `sub_category`，是唯一的知识维度（算法 / Java / 数据库 / 前端…），每个 tag 有稳定数字 id，如 Java=1、算法=8、Golang=29。
_Avoid_：分类、频道

**分组**：
tag 文件内部的知识体系统一分类（如算法下的「动态规划」「树与二叉树」）。由 `repos/wiki/scripts/topk-groups.mjs` 的关键词表决定：组顺序固定，首个命中的关键词胜出，没命中的进「其他」。
_Avoid_：子分类、章节

**次数**：
一道题在面经统计里被提及的次数，即站点字段 `vote`。排序与展示都以它为准。
_Avoid_：热度、票数

**快照**：
一次抓取得到的「tag → 题目 + 次数」原始数据，落成 JSON 提交进仓：既可离线重生成 markdown，也可与下次抓取 diff。
_Avoid_：缓存、dump

> 纠正（2026-11-19，`repos/wiki` `6b2d31b` / `042ebb2`）：下面四个词（思维导图 / 节点 / 概述 / 引用）描述的是 2026-11-13~11-17 的自研插件形态。站点 2026-11-18 已撤下 mindmap 插件、2026-11-19 改用官方 mermaid 主题，`<Mindmap>` 不再有组件接收；现在做图用 mermaid 代码围栏（[ADR 007](adr/007-导图退出站点改用mermaid主题.md)）。

**思维导图**：
文档正文里 `<Mindmap>…</Mindmap>` 之间的 markdown 标题渲染成的只读图，由 `@kxh4892636/docusaurus-plugin-mindmap` 提供。它是正文里的一个块，不是页面：导航、搜索、面包屑仍走 docs 原生逻辑。只有标签内的标题算导图；标签外的标题照常是正文标题、照常进文档目录。
_Avoid_：导图页面、图文档、导图路由

**节点**：
思维导图里的一个 markdown 标题，父子关系即标题层级。节点 id 就是标题开头的编号（`## 1.2 接口` 的 `1.2`），同图唯一；标题层级不跳级（H2 不能直接挂 H4），编号本身不要求连续（`1.1` 之后可以直接 `1.3`）。
_Avoid_：卡片、条目

**概述**：
节点标题下、下一个同级或更高级标题之前的普通正文，浮窗里逐行显示。
_Avoid_：描述、备注

**引用**：
节点下的 markdown 链接，两种。文档引用 `[说明](相对路径.md) doc:<文档id>`：跳转依据是链接后面的 `doc:` 后缀，渲染时换成 `/<文档id>` 短链、新标签页打开。节点引用 `[说明](#<编号>)`：锚点取编号，点了关浮窗并把图移到该节点。链接写在 `>` 引用块或普通段落里都算引用；同一段落里不带链接的正文仍是概述。
_Avoid_：链接、关联

**短链**：
一篇文档的站内另一条地址 `/<文档id>`，`<文档id>` 就是 front matter 里的 UUID `id`，由 `@kxh4892636/docusaurus-plugin-link` 生成（`shortRouteBasePath: "/"`，id 重复直接失败）。跨系统指一篇文档就用它——Anki 卡片背面写的就是 `https://wiki.kongxiaohan.cn/<uuid>`。没有 `id` 的文档没有短链。
_Avoid_：永久链接、permalink

> 纠正（2026-11-13，seq 4594）：`doc:<id>` 是链接后面的普通文本、不是链接目标，节点引用锚点是编号（`#1.2`）而不是任意节点 id；原条目把前者写成了链接目标。
