# 008-知识笔记目录对齐归档编号

## 背景

`020-计算机` 之前的二级目录是自拟的：`010-理论基础/{010-计算机网络,020-操作系统}`、`020-编程语言/{030-javascript,040-go}`、`040-系统设计/{010-数据库,020-分布式,030-架构与高并发,040-设计案例}`、`050-客户端/{010-react,020-vue,030-浏览器,040-css}`，多数是空壳，只有网络 6 篇与 React 7 篇有内容。

`090-归档` 的编号是另一套：计算机网络在 `010-理论基础/030`、操作系统并入 `050-计算机系统`、数据库教材在 `060-数据库系统`、产品与架构题在 `040-系统设计/001-007`、语言在 `020-编程语言`。

2026-11-21 用户在「八股文转知识笔记」开工前确认：目录按 `090-归档` 重排，既有笔记一并迁路径。

## 决策

二级目录与归档同名同编号，映射固定如下：

| 内容 | 目录 |
| --- | --- |
| 网络、浏览器渲染与缓存、性能 | `010-理论基础/030-计算机网络`（含 `100-浏览器渲染`、`110-浏览器缓存与内存`、`120-Web性能优化`） |
| 设计模式与发布订阅 | `010-理论基础/040-设计模式` |
| 进程、内存、IO、Linux 排查 | `010-理论基础/050-计算机系统` |
| HTML / CSS / JavaScript / Go | `020-编程语言/{010-HTML,020-CSS,030-JavaScript,040-Go}` |
| 构建、发布、代码治理 | `030-工程化/{030-构建与打包,050-代码治理}`（2026-11-23 平铺，见补记） |
| 基础设施、存储、分布式、通信、可靠性、案例 | `040-系统设计/{001-网络与基础设施,002-存储与建模,003-分布式数据,004-架构与通信,006-可靠性与安全,007-设计与案例}` |
| React / Vue | `050-客户端/{010-React,020-Vue}`（2026-11-23 删 Vue，见补记） |

例外只有 Vue：归档没有 Vue 目录，沿用 `020-Vue`。（2026-11-23 该目录已删，此例外作废，见补记）

## 依据

- 路径改名走 `git mv`，`git status` 显示为 `R`（rename），不是删加；
- 迁移时既有 13 篇笔记内 **0 条相对链接**，所以路径变化只需搬到新目录，不用改文内链接；
- 站内短链由 front matter 的 UUID 决定（`@kxh4892636/docusaurus-plugin-link`），与目录无关，迁移不改变任何 `/<uuid>` 地址；
- 侧栏 autogenerated，目录即结构，不需要改 `sidebars.ts`；
- 改完 `pnpm build` 通过（唯一失败源是本地草稿 `docs/000-中转/思维导图示例.md` 的 `<Mindmap>`，与本次迁移无关，见 [007](007-导图退出站点改用mermaid主题.md)）。

## 补记（2026-11-21 晚）

- 浏览器三块不再单开子目录：`100-浏览器渲染`、`110-浏览器缓存与内存`、`120-Web性能优化` 摊平进 `030-计算机网络`，该目录 25 篇连续编号（TCP → UDP → DNS/路由 → HTTP → 应用协议 → 浏览器）；
- 其余目录按「同一知识边界相邻」重排过编号（CSS、JavaScript、050-计算机系统、001-网络与基础设施、006-可靠性与安全、030-构建与打包），只改文件名，frontmatter `id` 全部原样，站内短链不变；
- 每级目录补了 `README.md` 索引，形态照 `090-归档`：H1 是目录名，下面是 `- [条目](./目标)`，不写描述。`020-八股文梳理` 因此第一次有了落地页，`docs/README.md` 才链得到它（构建是 `onBrokenLinks: throw`）。

## 补记（2026-11-23）

- `030-工程化` 取消 `030-构建与打包`、`050-代码治理` 两个二级目录：六篇平铺成 `001-Webpack打包原理` … `006-Git工作流与源码阅读`，`030-工程化/README.md` 改列六条；随后 003/004/005 合成一篇「代码质量闸门与测试」、006 顺延为 `004`，最终 `001`–`004` 四篇；
- `050-客户端/020-Vue` 整目录删除（4 篇笔记 + README）：该栏目只剩 `010-React`，「沿用 `020-Vue`」这条例外作废，Vue 只留在 `010-React/007-Vue与React的区别` 一篇做对照；
- 删目录必须连带修该级 README 的链接，否则 `onBrokenLinks: throw` 直接挡构建（`050-客户端/README.md` 已修）；
- Anki 牌组跟目录走：`030-工程化` 的两个子牌组并成一个、Vue 叶子牌组清空后删除，规则与验收见 [003-同步知识笔记的Anki卡片](../workflows/003-同步知识笔记的Anki卡片/003-同步知识笔记的Anki卡片.md)。

## 后果

- 归档与笔记同名目录在不同栏目下并列：`090-归档/010-计算机/010-理论基础/030-计算机网络` 与 `020-计算机/010-理论基础/030-计算机网络` 是两个物理目录，改内容时认准栏目；
- 新笔记编号在目录内连续（`001-`、`002-`…），归档是知识点级稀疏编号，两套编号别互相借鉴；
- Windows 上仅大小写不同的改名（`010-react` → `010-React`）`git mv` 会报 `Invalid argument`，要先改成中间名再改回；
- 空目录不进 git，删空壳目录不影响提交记录。
