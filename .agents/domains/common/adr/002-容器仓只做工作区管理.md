# 002-容器仓只做工作区管理

2026-11-14 的拆分把 `apps/*` 与 `packages/*` 九个目录各拆成独立 git 仓，平铺在 `repos/`；容器仓（远端 `kxh4892636/awesome`）从此只做工作区与仓库管理，不再有任何代码依赖。

拆分后的形态：

- 根只有 `.agents/`、`scripts/`、`workspace.yaml`、`README.md`、`AGENTS.md` 与运行目录；没有 `package.json`、`pnpm-workspace.yaml`、锁文件、`tsconfig*.json`、`node_modules`、`.node-version`、`.vite-hooks`。**根上再出现 `package.json` 就说明改造没做完。**
- 每个子仓自带 `pnpm-workspace.yaml`（只有 `allowBuilds` / `overrides` / `peerDependencyRules` / `minimumReleaseAgeExclude`，没有 catalog）、自己的 `pnpm-lock.yaml`、`tsconfig.base.json`、`.node-version`、`.gitattributes` 与 `.gitignore`。
- `catalog:` 一次性固化成真实版本写进各仓 `package.json`；依赖版本从此各仓独立演进。
- `repos/` 进容器仓 `.gitignore`，不引入 submodule；子仓清单是根 `workspace.yaml`。

## Considered Options

- **容器仓零代码依赖（选定）**：每仓独立 install、独立发布、独立演进；代价是磁盘占用上升（原来一份 0.8 GB `node_modules` 变成九份）与依赖版本不再天然对齐。
- **保留 pnpm monorepo（catalog + 根锁文件）**：省磁盘、版本单一源，但九个包的发布节奏被绑在一起，且发布包的生产依赖本来就不能写 `catalog:`（[001](001-发布包生产依赖不使用catalog协议.md)）。
- **submodule 或 turbo / nx**：容器仓要额外维护指针或工具链，用户明确不引入。

## Consequences

- 容器仓 `git status` 看不到子仓改动；改代码要进 `repos/<名>`，`.worktrees` / `.temp` 约定由各子仓自己执行。
- 跨仓依赖不能再写 `workspace:*`，只能走制品 URL（[003](003-跨仓制品走仓内tgz与raw链接.md)）。
- 验收判据：根上无 `package.json` / `node_modules` / 锁文件；`repos/` 下九目录各有 `.git` 且工作树干净；`git -C repos/wiki ls-files docs/010-记录` 为 0 且 `git status --ignored` 仍显示 ignored（私有内容不上传）。
- 历史 Plan 里的 `apps/`、`packages/` 是当时的现场记录，不再更正；活文档统一写 `repos/<名>`。
