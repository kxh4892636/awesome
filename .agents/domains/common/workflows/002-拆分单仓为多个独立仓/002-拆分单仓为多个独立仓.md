# 002-拆分单仓为多个独立仓

## 触发条件

一个 pnpm 单仓里的多个包需要独立演进、独立发布、各自装依赖，决定每包一仓、平铺在 `repos/<名>`。只想换目录结构、不拆仓的整理不必走这套。

## 步骤

1. **筛分与定约定**：列清「目录 → 子仓名 → 包名 → 可见性」，定哪些根文件保留、哪些下沉（锁文件、toolchain、tsconfig 基线、catalog 版本）。同时盘出仅存在于磁盘的 ignored 私有内容——它们必须**整目录搬走**且搬完仍被忽略。
2. **抽目录历史**：每目录 `git subtree split --prefix=<目录> -b split/<名>`。量级参考：1400 提交的仓里每个目录 110–210 秒，九条串行约 25 分钟，放后台任务跑。
3. **搬目录并挂历史**：先删该目录 `node_modules`（里面的 dangling symlink 会让 `Move-Item` 半途失败并留下嵌套目录）→ 整目录一次搬完 → `git init -b main` → `fetch` 容器仓的 `split/<名>` → `update-ref refs/heads/main FETCH_HEAD` → **`git reset`（mixed）**。不要用 `reset --hard`：工作区已就位，硬重置有覆盖私有文件的风险。
4. **独立化改造**：`catalog:` 全部换成真实版本；仓内补 `.gitattributes`、`.node-version`、`tsconfig.base.json`（`extends` 改指仓内）、`pnpm-workspace.yaml`（只留 `overrides` / `allowBuilds` / `peerDependencyRules` / `minimumReleaseAgeExclude` 设置段，不写 `packages` 键）、`.gitignore`（node_modules / dist / coverage / tgz / tsbuildinfo）；`repository`、`editUrl`、首页链接里的旧仓名一并改。
5. **逐仓过门禁**：`pnpm install` → `vp check --fix` → `check` → `test` → `build`，全绿后提交。**build 必须真跑**，见下面第一条坑。
6. **接跨仓依赖**：不能再用 `workspace:*`，改制品 URL（[ADR 003](../../adr/003-跨仓制品走仓内tgz与raw链接.md)）。
7. **建远端并推送**：浏览器建仓（[008](../../questions/008-用bsk操作GitHub时为什么会失败.md)）→ 加 `origin` → 推 `main`。仓名已被占用时先 `git clone --mirror` 备份旧内容，再 `push --force`。
8. **收口**：容器仓 `.gitignore` 加 `repos/`（否则子仓会被当成 embedded repo）→ 提交删除 + 清单 → 在根 `workspace.yaml` 登记九个条目 → 活文档里的旧路径改成 `repos/<名>`。

## 验收

- 容器仓：根上无 `package.json` / `node_modules` / 锁文件 / `tsconfig*`；`git status` 干净；`repos/` 被忽略。
- 每个子仓：`git status --porcelain` 为空；`git log --oneline` 的提交数与该目录 split 分支一致。
- 私有内容：`git -C repos/<名> ls-files <私有目录>` 为 0，`git status --ignored` 仍显示 ignored，文件数与搬迁前一致。
- 跨仓安装：消费方 `pnpm install && pnpm build` 通过，lockfile 里记录的是 URL 而非 `workspace:`。

## 已知坑

- **脱离根锁文件后传递依赖会漂移，只在 build 暴露**：wiki 独立安装把 `hast-util-to-estree > style-to-js` 解析成 `1.0.0`（根锁文件是 `1.1.21`），新版本解析 KaTeX 的 style 属性直接让整站 MDX 报 `Could not parse style attribute on span`。修法是在该仓 `pnpm-workspace.yaml` 的 `overrides` 里锁回 `1.1.21`。
- **子仓的 `pnpm-workspace.yaml` 不是 monorepo 残留**：它是 pnpm 设置的唯一载体（`overrides` / `allowBuilds` / `peerDependencyRules` / `minimumReleaseAgeExclude`），`.npmrc` 装不下这些。只删顶上的 `packages: []`，整文件删除会退回真 vite / vitest 并让冻结安装失效（[009](../../questions/009-子仓的pnpm-workspace.yaml能整删吗.md)）。
- `vp check` 会挑 `package.json` 的 JSON 缩进；写完统一 `vp check --fix` 再提交。
- 原来靠根忽略项覆盖的条目要补进各仓 `.gitignore`（如 etf 的 `.vitest/`）。
- 历史重写不可逆：`split/<名>` 分支留在容器仓里当回滚点，确认无误再删。
- 搬完目录后，历史 Plan 与旧文档里的 `apps/`、`packages/` 是现场记录，不追改；活文档才统一成 `repos/<名>`。
