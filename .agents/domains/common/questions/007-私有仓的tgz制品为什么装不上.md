# 007-私有仓的tgz制品为什么装不上

## 适用条件与现象

让一个仓从 GitHub 装另一个仓的构建产物，而来源仓是 private：下面两类 URL 都返回 404，同一个地址在登录的浏览器里却能打开。

- `https://github.com/<owner>/<repo>/releases/download/<tag>/<file>.tgz`
- `https://github.com/<owner>/<repo>/raw/main/release/<file>.tgz`

`pnpm install` 报下载失败或 `ERR_PNPM_FETCH_404`。

## 原因

私有仓的所有下载通道都要凭据，而 pnpm 的 HTTP fetcher 不带 GitHub token。「浏览器能下载」不等于「安装方能下载」。

## 解决方法

1. 把来源仓改 public（Settings → Danger Zone → Change visibility）。
2. `pnpm pack` 出的 tgz 提交进来源仓 `release/`，`.gitignore` 加 `!release/*.tgz` 放行。
3. 消费方依赖改写成 raw URL（[ADR 003](../adr/003-跨仓制品走仓内tgz与raw链接.md)）。
4. 临时联调可退回 `file:../<仓名>`，但那要求两个仓平级在 `repos/` 下。

## 验证

- 匿名可下载：`curl -I <raw url>` 返回 200，或无痕窗口能直接下载。
- `pnpm install` 后 `pnpm-lock.yaml` 里该依赖的 specifier 与 version 都是这个 URL。
