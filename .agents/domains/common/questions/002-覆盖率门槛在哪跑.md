# 002-覆盖率门槛在哪跑

## 适用条件与现象

验收要求「覆盖率达标」，但工作区根上找不到阈值配置，不同仓报出的门槛也不一致。

> 纠正（2026-11-22，dream 复核；依据 [common ADR 002](../adr/002-容器仓只做工作区管理.md) 与九仓现状）：容器仓已无 `vite.config.ts`，也不再有一次跑全仓的根命令；阈值全在各自子仓，验收按仓逐个跑。

## 原因

阈值写在子仓自己的 `vite.config.ts` 或 `vitest.config.ts` 的 `test.coverage.thresholds`，四项指标同值：`nano-flow` 90，`dsh-toolkit`、`pi-toolkit`、`etf`、`music` 各 80；其余仓没有配置阈值。

## 解决方法

进目标子仓执行 `vp test --run --coverage`；多仓验收逐个仓跑各自的 test 脚本。以目标仓配置为准，不套用其他仓的数字。

## 验证

coverage 报告不因阈值失败，且四项指标均达到该包配置值。
