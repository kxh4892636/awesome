# 020-飞书画板忽略svg类样式

## 现象

把 diagram-design 的 `example-loop.html` 用 `export_svg.py` 导出后直接放进 `<whiteboard type="svg">`，画板里所有节点变成黑块，节点名和子标签看不见；同一份 SVG 在浏览器里是正常的。换成属性直接写在元素上的 architecture 示例，画板渲染正常。

## 原因

飞书画板的 svg-parser 只读取元素的 presentation attributes，不执行 `<style>` 和 class；diagram-design 的 loop / process / medallion 等类型把 fill、stroke、字体写在页面 CSS 里，导出时虽然把 CSS 搬进了 SVG 的 `<style>`，画板仍然忽略。文字没有独立的 `fill` 时继承默认黑色，叠在黑底上就消失。

## 影响

只影响「类样式驱动」的 SVG。architecture 这类把属性写在元素上的图不受影响。画板对 `<pattern>`、`<clipPath>`、`<mask>`、非阴影 `<filter>` 也不支持；点阵背景、裁剪和阴影可能被降级或丢图。

## 判别

- 画板预览出现整块黑色、文字消失，但浏览器打开 SVG 正常。
- 导出的 SVG 里有 `<style>` 或 `class=`，元素自身没有 `fill` / `stroke`。

## 处理

嵌入前跑 pretty-doc 的转换器：

```bash
python3 <pretty-doc-root>/scripts/larkify_svg.py diagram.svg diagram.lark.svg \
  --palette <pretty-doc-root>/assets/lark-palette.json
```

它把 CSS 内联成属性、映射色板、删不支持特性、换白底。转换后确认 SVG 里没有 `<style>` / `class=` / `<pattern` / 外链。

## 验证

2026-11-24 实测：loop 示例原样嵌入为黑块；转换后节点、文字、箭头、焦点色均正常。architecture 示例转换后点阵被删、白底、焦点色映射为 `#245bdb`。证据见 [003-画板svg链路](../plans/active/2026-11-24-美观文档技能/003-画板svg链路.md)。
