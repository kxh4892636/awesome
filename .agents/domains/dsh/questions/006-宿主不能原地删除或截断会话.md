# 006-宿主不能原地删除或截断会话

## 适用条件与现象

想让某个会话「变短」—— 历史被遮蔽、模型只看到前面一段（轮转重置上下文就是这么做的）—— 而宿主没有删除/截断日志的 API。

## 原因

会话日志是仅追加的事件源记录，删除/截断事件与会话的 API 都不存在；存活会话优先于磁盘；改文件后存活会话继续按旧游标追加，读取端会因 seq gap 判定损坏。

但「日志不能截断」不等于「模型可见历史不能变短」：**表面**（模型看到的历史）能变短。`SurfaceOp` 只有 `"append"` 与 `{op:"replace",startSeq,endSeq}`，后者把 N 个节点换成 1 个新节点 —— 这是唯一手段，代价是必须留下一条节点。

## 解决方法

按 `surfaceOp.replace` 写一条替换事件：

- 起点、终点都必须是**当前表面上**的节点；`sourceEventSeqs` 要逐个覆盖被遮蔽节点，漏一个宿主就拒写。
- 替换者要选「不投影出消息」的类型或形状，否则模型会看到一条凭空的对话：空 content 的 `system/message` 不投影任何消息（轮转用的则相反 —— 它要塞 seed，所以用 `user/message`）。
- 想同时让 token 记账跟着缩水，得先在紧邻位置写 `compaction/prune`（`shadowedTokenCount` 必须用 `heuristicTokens`，不是路由价），否则折叠按 0 delta、压力虚高。
- node 0 若持有系统提示，只能被同位置的 `system/message` 重写。

## 验证

手写 `surfaceOp.replace` 的那版轮转（`clearSurface`）已随 0.5.61 整个删掉，现在这条规律由宿主的 compact 引擎自己兑现：它压完写一条 `source.kind='compact-checkpoint'` 的用户消息遮蔽旧区间，轮转只是它的调用方。真机证据见 [009-轮转复用宿主compact](../plans/reference/2026-11-16-轮转保持原会话/009-轮转复用宿主compact.md)。
