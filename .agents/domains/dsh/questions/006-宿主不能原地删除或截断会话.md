# 006-宿主不能原地删除或截断会话

## 适用条件与现象

想让某个会话回到上一轮结束的状态，并要求「同一个 session id 变短」（原地撤销），同时不想杀掉该会话上的子 agent 与后台 job。

## 原因

会话日志是仅追加的事件源记录，删除/截断事件与会话的 API 都不存在；存活会话优先于磁盘；改文件后存活会话继续按旧游标追加，读取端会因 seq gap 判定损坏。

但「日志不能截断」不等于「会话不能回到上一轮」：**表面**（模型看到的历史）能变短。`surfaceOp` 只有 `"append"` 与 `{op:"replace",startSeq,endSeq}` 两种，后者把 N 个节点换成 1 个新节点——这是宿主唯一能让表面变短的手段，代价是必须留下一条节点。

## 解决方法

追加一条墓碑事件（`system/message`，空 content 不投影出任何消息），替换区间从切点到表面结尾：

- `data.recall {boundary, end}` 是给客户端读的标记；`turn`/`step` 必须是正整数（v4 准入）。
- `boundary` 必须仍在表面上且是 `append` 起源的用户/助手消息；`sourceEventSeqs` 要逐个覆盖被遮蔽节点，漏一个宿主就拒写。
- 撤回前清空该会话排队中的输入，否则待发消息立刻开一轮，把刚遮蔽的历史重新长出来。
- 界面隐藏交给客户端：读 `data.recall` 后把区间内的视图节点置 `visibility:"hidden"`（宿主 `isVisibleChatNode` 按它过滤），用户提问行由同 key 的 `conversation.chat.node` seat 接管后不渲染。
- 不写 `compaction/prune`：写了就会按 claim 记账，而撤回只是想变短；代价是上下文占用会虚高到下一次真实压缩。

## 验证

`repos/dsh-toolkit` 的 `undo-turn` 单测覆盖墓碑形状、覆盖集合、切点离面拒绝、忙碌拒绝与队列五种情形；`recall-hide` 单测覆盖区间命中、`visibility` 改写与 seat 委托；真机验收看 README 验证第 4 步（那一轮从对话里消失、会话 id 不变、日志多一条墓碑）。
