# 019-轮转后输入里的skill手势还触发吗

## 现象

用户报「输入里调了 `/pp`，正好触发轮转，轮转之后 skill 没触发，被当成普通字符串」。观感是手势在轮转里丢了。

## 结论（2026-11-21 核对）

- **触发那条输入里的手势不会丢。** 手势扫描只受理 `source.kind === "user"` 的消息文本块，正则是 `(^|\s)\/([a-z0-9]+(?:-[a-z0-9]+)*)(?=\s|$)`（`@deepseek-ai/dsh-tool-skill/lib/index.js:1109` 的 `SKILL_GESTURE`、`:1117-1130` 的 `invokedSkillNames`）。轮转的种子是一条用户消息、用户原话原样在里面，所以 `/pp …` 照样命中。
- **实测三个会话逐一比对**：`session-644c9eec…`（轮转出来的目标会话，种子里 `/pp`、后一条 `/ponytail`）、`8f59…`（`/ask`、`/do`、`/hallmark`）、`ccb8…`（`/ask`×4、`/to-skill`、`/do`）——全部有对应的 `skill-invocation` 消息，没有一例是真丢。
- **会丢的是更早轮次的技能正文。** 种子只带「当前 Plan + 上一轮输出 + 触发轮转的那条输入」，所以「对本会话全程有效」这类技能，若在更早的轮次调用，轮转后就只剩技能目录摘要，正文没了。
- **静默失效的手势标点**：`/name` 后面必须紧跟空白或行尾。`/pp，帮我看看`（全角逗号）、`/pp。`、`/pp:` 都不命中，被当普通文字——这最像「转义成普通字符串」的现象。
- **界面上看不见**：种子是一整段文本，`/pp` 以纯文本躺在里面；技能芯片是另一条注入消息，不一定紧贴显示。别把「没看到芯片」当成没注入。
- **定时投递是另一条路**：source 是 `schedule` 时手势一律不注入，见 [017](017-定时投递的dream取不到技能.md)。

## 判别

先看新会话第一条消息里有没有手势原文（有 → 走上面第 1 条，别急着改代码），再确认是「更早轮次调用的技能」（第 3 条，功能缺口）还是「标点没跟空白」（第 4 条，改写即可）。

## 未决（2026-11-21）

「把本会话注入过的技能随种子带过去」是真的功能缺口，改点在 `repos/dsh-toolkit` 的种子构造与预设提示词；用户当轮没有定方向，没动代码。
