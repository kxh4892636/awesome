# 005-优化示例文档

## 目标

飞书文档 [九个仓怎么协作](https://bytedance.larkoffice.com/docx/RkLadY1OIohi9Jx03k4cg0ChnLc) 是 004 的示例产出。本轮按 pretty-doc 的版式与文风重写正文，保留同一链接与画板。

## 改了什么

- **补九仓清单**：原文只写「九个包」，读者无法对应到 `workspace.yaml`。加一张四行分类表（应用 / 站点 / 插件 / 工具包），来源是容器仓 README 与 `workspace.yaml`。
- **验收给命令**：原文 blockquote 写「三条命令能查完」，正文却没有命令。改成「四条检查，ls 与 git status 就能查完」，左栏要点换成可照抄的检查项。
- **升版写成四步**：「下一步」原是一句话塞了五个动作，改成 pack / 提交 / 换 URL / 收尾四步。
- **修订现场事实**：wiki 只依赖 link 插件的制品（`repos/wiki/package.json`，mindmap 已从站点撤下）；根目录补 `inbox/`；单仓时期补回 0.8 GB 与 `catalog:` 的具体代价。
- **保留**：结构图、三个关键决定、三个坑的表格；画板原样重嵌，token `XnikwO848hpYkCbys5acvUe8nFe`。

## 真机回读发现

- 新加的九仓表按版式文档写了 `colgroup`（150/390/460），页面上整表撑出正文宽度、第三列被裁；换成 220/380/400、再换成与坑表相同的 300/380/320，仍然溢出。
- 去掉 `colgroup` 后 Lark 自适应列宽（82/328/328），表格收进正文宽度，四行内容完整。结论：内容重的表先不写列宽；坑表保留 `colgroup` 时渲染正常，不能一概而论。
- 左栏原先把 `pnpm-workspace.yaml` 折在连字符处，已改成顿号分隔的检查项。

## 验收

- `lark-cli docs +script --command parse` 返回 `passed`（1044 词，5 个 h1）。
- 正文 `block_replace`（首个 callout 到文档尾，revision 16）＋两处 `str_replace`（18、19）＋表格两次重写（21、22）；回读结构：5 个 h1、2 张表、4 个 callout、1 个 grid、1 个画板。
- 画板预览（`whiteboard +export`）文字完整、箭头未丢、只有蓝一个强调色。
- 浏览器实机截屏复核：TLDR、九仓表、坑表、双栏 callout、下一步列表均正常，无横向溢出。

## 事实核查

- `workspace.yaml` 九条，path 全在 `repos/`；本机只 clone 了 dsh-toolkit、pi-toolkit、wiki 三个，正文写「按需 clone」。匿名 `git ls-remote` 对 wiki 与 dsh-toolkit 均返回 HEAD，public 成立。
- 三个子仓的 `pnpm-workspace.yaml` 顶部仍有 `packages: []`（2026-11-24 实测），「只删这一行」仍是操作建议，不是已完成状态。
- 容器仓 README 仍写「跨仓依赖走 GitHub Release 的 .tgz」，与 ADR 003 冲突；属 README 的旧表述，本轮未改文档外内容。
