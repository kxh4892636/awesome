# 006-撤回在同一会话内完成

## 背景

用户提出：撤回（undo / 撤销到某一轮）现在跟旧轮转一样是**新建会话**，那能不能套用 003 的思路 —— 在原会话里把表面截断到目标轮，会话 id 不变，子 agent 与后台 job 继续跑。

## 待查（本轮 subagent）

1. **插件侧**：撤回的入口（工具/面板/路由）、实现链（`host/undo/*`）、它现在为什么必须换会话、涉及哪些旁路状态（Plan 绑定、`log.jsonl` 轨迹、note 板、tombstones）。
2. **宿主侧**：除了 `surfaceOp:{op:"replace"}`，宿主有没有更贴近「回到第 N 轮」的能力（fork / rewind / `compaction/prune` 区间语义 / session-query），以及表面变短后 tokenMeter 与持久化重放是否自洽。

## 插件侧事实（undo-probe，2026-11-16）

- **入口三条，模型侧没有入口**：composer 按钮（`client/index.ts:39-49`，slot `conversation.input.right`）、`GET /api/toolkit/undo-turn` 探测可用性（`host/toolkit-routes.ts:70-75`）、`POST` 执行（`167-190`，工具关闭 409、宿主不支持 501）。工具目录项 `undo-turn` 的 `apply` 是空实现（`host/tools/undo-turn.ts:8-13`），只当开关键用。
- **主链不是 `create()`，是 `fork`**：`resolveTarget` → `capturePlacement` → `controller.fork({sessionId, atSeq: cutSeq})` → `archiveSession(id,{stopActivity:true})` → `adoptPlacement`（记账位与置顶）→ `retireSource`（`addPendingDelete` + 150ms settle + `deleteSessionLogs` + `unarchive`）（`host/undo/undo-turn.ts:70-80, 172-180`）。`atSeq` 是**闭区间上界**，即取 `0..cutSeq` 前缀。
- **切点语义**：从日志末尾找最后一个 `turn/start` 定轮，`cutSeq = startSeq-1` 再向前跳过 `agent/inbox/*` 记账事件（`host/undo/turn-boundary.ts:54-80`）；seq 必须等于数组下标，否则判不可撤回。同一轮的 `user/message` 文本合成「原文」，非文本与运行时注入被排除（`83-102`）。
- **杀活链是归档，不是撤回本身**：`archiveSession({stopActivity})` → `workspace/session-stop` → `dsh-agent` cancel、`dsh-jobs` 对 running job 逐个 kill、`dsh-subagent` cancel 祖先为该会话的子 agent。插件里没有任何 job/subagent 相关代码。
- **Plan 绑定不搬**：`UndoDeps` 里没有 `rebindSession`；原绑定留在表里等 `pruneDeadBindings` 清。子会话无绑定 → note 板空白（`index.ts:492-493`）。
- **轨迹不删**：只 `planLog.forget(sessionId)` 关读句柄，已写入的 `log.jsonl` 行原样留着（全文件无删除路径）。
- **墓碑两层**：宿主 `state.json: hiddenSessionIds`（`announceRemoved`）+ 客户端 `localStorage`（`tombstones.ts`）。
- **测试**：约 73 条（`turn-boundary` 10、`undo-turn` 13、`purge` 13、`purge-fs` 4、`undo-button` 11、`tombstones` 9、路由 5、`index` 2、`host-api` 4、目录项 1）。没有「不搬绑定 / 不新建会话」的反向断言。
- **客户端 5 处依赖「会换会话」**：`openSession(childSessionId)`、草稿按子会话 id 存、1.5s 兜底按子会话 binding、摘原行 + 两次目录刷新、note 板随 sessionId 重挂。

## 宿主侧事实（surface-probe，2026-11-16）

- **只有一个写入口**：`Session.append(…, {surfaceOp})`；没有跳过/删除节点的 API。`SurfaceOp` 只有 `'append'` 与 `{op:'replace',startSeq,endSeq}`（`dsh-session/src/types.ts:470-472`），**没有 truncate/remove**。
- **replace 是 N→1**：`applySurfacePlan` 用 `splice(startIdx, n, seq)`（`surface.ts:569-591`），表面必然变短，但**必须留下一条新节点**；node 0 若是系统提示，只能被同位置的 `system/message` 重写（`485-504`）。所以「表面 = 历史前缀」表达不出来，只能是「前缀 + 1 条合成节点」。
- **硬校验**：replace 两端必须存在于当前表面（`413-434`）、`sourceEventSeqs` 必须逐项覆盖被遮蔽节点（`329-365`）、`assistant/message` 永远不能做 replace（`335-337`）、`tool/result` 只能一对一且只改 content（`454-483`）。
- **表面收缩合法**：tokenMeter 的 `surface-fold` 按节点价差记账，负数自然成立；`projectedTokens = max(0, pressure + surfaceTokens - sampled)`（`usage-projection.ts:186-212`）。
- **prune 必须紧邻 replace 且区间完全一致**：不一致 → `token surface: replace at seq … has no adjacent shadow price`（`surface-projection.ts:89-94`）；中间插了别的任何事件 → claim 静默过期、按 0 计（`79, 88`）；落盘 restore 时 `shadowedSeqs` 必须逐项等于当前表面切片，否则 `shadowedSeqs do not name an exact current surface span`（`relationships.ts:255-264`）。
- **宿主没有 rewind/undo/truncate**：全包清单无此类包，控制器方法面里只有 `fork`（`commands.ts:224-300`）。`fork` = 取 `0..atSeq` 前缀 + `session/end-seed{inherited:true}` + 补闭合事件，建**独立子会话**；父会话不变（`dsh-session/src/fork.ts:10-30`、`index.ts:1467-1500`）。
- **`compaction/start…end` 是锁**：未闭合期间不能开新的、`turn/*` 不能穿过（`relationships.ts:226-272`）；成功 `compaction/end` 必须已有 `compaction/summary`（`243`）；非 append 的 `user/message` 若 `source.kind==='compact-checkpoint'` 必须有匹配的 `compaction/start`（`319-321`）。
- **GUI 不会因表面变化删行**：transcript 只由 **append 起源**的 `user/message` 生成（`dsh-client-ui-chat/.../conversation-nodes/message.ts:82-90`），兜底节点同样要求 append（`fallback.ts:19`）；唯一会渲染的 replace 形态是 `source.kind==='compact-checkpoint'` 的检查点行（`command.ts:78-137`），且 `CompactionItem.tsx:1-5` 注释写明「标记不替换被遮蔽的行」。搜索侧反而会排除 `shadowed`（`dsh-api-session-controller/src/list.ts:240`）——「搜不到」会比「看不见」先发生。
- **撤不回来的东西**：turn 计数来自 log 投影（`dsh-agent-loop/src/index.ts:568`），job 归属按 owner session id 围栏（`dsh-jobs/src/index.ts:63`），subagent catalog 是 session projection（`dsh-subagent/src/index.ts:216-223`）。表面截断都不回退它们。

### 两个可选形态

| 形态 | 写法 | 观感 |
| --- | --- | --- |
| A「压缩标记」（推荐） | `compaction/start` → `compaction/prune`（改用 heuristicTokens）→ 一条 `user/message`（`source.kind:'compact-checkpoint'`，`surfaceOp.replace` 盖住 cutSeq 之后的全部节点）→ `compaction/summary` → `compaction/end` | GUI 新增**一条标记行**（「已撤回，遮蔽 N 条 / M tokens」），旧行仍在；模型只看到标记后的表面 |
| B「原文归位」 | 只 prune + 一条 replace 的 `user/message`（普通 source，内容 = 那轮原文） | GUI **不新增**任何行，模型像「刚收到这条消息」，可能直接把它重跑；turn 号跳号 |

- 两种都做不到「界面上把消息删掉」，除非改客户端按 surface 过滤（宿主客户端目前没有这条通道，属新工作量）。
- 形态 A 附带好处：走的是宿主既有 compaction 协议，restore/tokenMeter/客户端三处校验都覆盖到了。

2. turn 号**不回退**（继续 +1）、inbox/队列不清空 —— 能接受吗？

### 顺带发现（不是本次改动引入，是本 Plan 的 0.5.56 代码）

`rotate.ts` 的 `shadowedTokenCount` 用的是 `measure().nodes[].tokens`（按路由定价），但影子价格协议要求 `heuristicTokens`（`dsh-token-meter/src/types.ts:37-53` 原文 + 参考实现 `dsh-compaction-basic/src/region.ts:378-381`）。claim 只比对区间端点、不校验数值，所以不会报错，只会让重置后的 `projectedTokens` 少算（触发点偏晚、面板压力偏低）。待与撤回改动合并发布。

## 用户裁决（2026-11-16 20:31）

1. 界面里被撤回的消息**必须不可见**（不接受「模型失忆、界面留痕」）；
2. 撤回要**清空**队列 / inbox；
3. 轨迹里不用加「已撤回」标记。

原话：「我的预期就是和 fork 一样，但是不新建会话，直接在原会话修改，不能复用 fork 的逻辑吗？」

## 结论：fork 的切点能复用，落地方式不能复用

fork 做两件事：算切点（`turn-boundary.ts`，可复用）+ **造一份新日志**（`buildForkSeed`：拷 `0..cutSeq` 前缀 → `session/end-seed{inherited:true}` → 补闭合事件），把它塞进**新会话**。原会话里我们拿不到「日志变短」这件事：

- 日志 append-only、seq 必须连续、宿主是唯一写者（`dsh-session/src/surface.ts:506-518`）；
- 插件唯一写入口是 `Session.append(..., {surfaceOp})`，而 `SurfaceOp` 只有 `append` 与 `replace`（N→1），没有 truncate（`types.ts:470-472`、`surface.ts:569-591`）；
- 界面行只由 **append 起源**事件生成，且客户端节点注册表按**注册顺序**匹配、内置 `message` 定义先注册、没有 filter 缝（`dsh-client-ui-conversation/src/client/conversation/event-registry.ts:24-70`、`dsh-client-ui-chat/.../conversation-nodes/message.ts:180`）—— 插件抢不到 `user/message` 的匹配权；
- turn 号、inbox、job 归属、subagent catalog 全部从日志投影或按 session id 围栏派生（`dsh-agent-loop/src/index.ts:568`、`dsh-jobs/src/index.ts:63`），表面截断不回退它们。

所以三条要求合并起来 = **宿主的 rewind 能力**，插件层无解。

### 最小宿主方案（若要推）

1. `SurfaceOp` 增 `{op:'truncate', atSeq}`（或允许 replace 的「空替换」），表面折叠时把 `> atSeq` 的节点整体视为 shadowed；
2. `turnBoundaryOf` 认 `session/rewind`，下一轮 turn 号取 `atSeq` 之前最大 turn + 1；
3. `history/listener` 收到 rewind 后截断客户端 buffer（分页侧 `isAppendSurfaceEvent` 过滤已天然支持）；
4. 宿主执行 rewind 时清 `queued` / `pendingInput`。

插件层现在**能做**的部分只有「清队列」：`controller.updateQueue({sessionId, itemId, action})` 逐条移除（`dsh-api-session-controller/src/index.ts:509-511`）。
