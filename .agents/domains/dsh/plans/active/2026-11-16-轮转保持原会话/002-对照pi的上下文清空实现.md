# 002-对照pi的上下文清空实现

## 机制：pi 是「写标记 + 每请求过滤」

1. 触发点 `before_agent_start`，仅 user 消息、`tokens/contextWindow >= rotateAt`（默认 0.618）且「reset 之后已产生新 assistant」时才动手（`src/nano-flow/register.ts:176-200`）。
2. 动作是 `pi.appendEntry("nano-flow-reset", { at, seed })` —— 一条 **custom 会话条目**，不是命令也不是消息（`mode.ts:17`）。
3. 每次请求前，`context` 钩子取最新 reset，丢掉 `timestamp < at` 的消息，把 seed 作为一条 `role:"user"` 消息插到队首（`register.ts:221-235`；宿主侧 `dist/core/extensions/runner.js:1014-1073` 每步请求都跑）。磁盘上的会话文件一条不删。
4. 激活期间 `session_before_compact` 一律 cancel，防止自己的压缩把清空前历史摘要塞回来（`register.ts:237-239`）。
5. `fresh` 门闩防止同一条高占用被连击。

**更正一个前提**：`nano-flow-reset` 不是可调用命令，只有自动触发。之前 spec 里「上下文清空（`nano-flow-reset`）」的说法按此修正。

## 为什么 dsh 不能照抄

dsh-session 的契约是 **Model-visible means logged**：模型历史只能由会话日志投影（`session.deriveMessages()`），agent loop 没有 per-request 改 messages 的钩子（`agent/pre-step` 只拿 inbox 新消息，`agent/request` 只拿请求配置）。等价物只能是**追加一条 surface replace 事件**——它是**持久**的，与 pi 的 ephemeral 过滤不同。

## 可照搬 / 不可照搬

| 可照搬 | 不可照搬 |
| --- | --- |
| 不删会话（这条本身就是用户诉求）：去掉 `archiveSession` / `deleteSessionLogs` 后，子 agent、后台 job、todo 全部存活 | `context` 钩子过滤：dsh 无此接缝，改为持久遮蔽 |
| 触发点：压力检查挂在 user 消息进入时，即现有 `sessionController.prompt` 包装（`rotate.ts:491-510`） | 「激活期间取消压缩」：dsh 压缩只看可见表面，遮蔽后表面变小自然无物可压，没有 `session_before_compact` 这类全局取消 |
| seed 内容：dsh 的 `buildSeed` 已比 pi 完整，去掉「绑定已过继」分支与 autoCheck 段落即可 | pi 的 `fresh` 门闩不能原样用：dsh 只要发了 `compaction/prune` 影子价，占用就会降；不发则会连击 |
| 压力账要有配套：遮蔽必须发 `compaction/prune`，否则 replace 按 0 增量折叠、占用条不降 | 会话面板语义：GUI 仍显示旧消息，只有模型看不见 |

## 风险

1. **语义降级且不可逆**：dsh 版是日志级持久遮蔽，重置后重启、导出、fork 都看不到旧历史；pi 的 `/tree` 与导出仍然完整。需要用户确认。
2. **压力账算错就退化成每轮重置**：漏发 prune 时 `surfaceTokens` 折零，占用不降，每轮都触发。
3. **replace 边界写错当场抛错**：范围要覆盖全部被遮蔽节点、工具调用与结果配对平衡、system 头节点不能被 user 消息替换；`rotate.ts:483-488` 的失败回落必须保留。

## 用户决策（2026-11-16）

- 「重置后界面历史仍在、只有模型失忆」的观感 —— **可接受**。因此不需要额外的视觉分隔事件，也不需要改客户端会话视图；003 步骤 7 里「插入分隔事件」的可选项作废，只保留设置面板文案说明。
- 由此确认采用**持久遮蔽**（surface replace）而不是寻找 per-request 过滤：dsh 没有那个接缝，且用户接受持久化的后果。
