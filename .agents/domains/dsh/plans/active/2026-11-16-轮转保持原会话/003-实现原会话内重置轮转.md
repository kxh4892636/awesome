# 003-实现原会话内重置轮转

## 做了什么

触发条件不变（queue 消息、非子 agent、nano-flow 预设、`projectedTokens ≥ rotateAt × contextWindow`）。动作从「建新会话 + 归档 + 删旧会话」改为**原会话内遮蔽历史**。

`repos/dsh-toolkit/src/nano-flow/session/rotate.ts`：

- 新增 `clearSurface`：保留 `surface.nodes[0]`（系统提示），对其余节点先 `append("compaction/prune", { shadowedRange, shadowedSeqs, shadowedTokenCount })`（价格取 `tokenMeter.measure(session).nodes` 的 `tokens` 之和），紧邻再 `append("user/message", { content: [seed] }, { surfaceOp: { op: "replace", startSeq, endSeq }, sourceEventSeqs })`，最后 `sessions.flush(session)`。
- 删除 `retire` / `inheritPlacement` / `adoptBinding` 过继链：不再 `archiveSession`、`detachSession`、`recordPendingDelete`、`deleteSessionLogs`、`onRotated`，也不再包 `<rotation-prior-input>`（同一会话，原文直接发出）。
- 新增两道闸：`turnClosed`（回合没结束时不动表面，避免抽掉当前步骤之后要用的历史）、`advancedSince`（重置后必须产出过新的 assistant 消息才允许再次重置，对应 pi 的 `fresh` 门闩，防遮蔽价失真时连击）。
- 任一步抛错只 warn，prompt 照常发给同一会话（消息不丢）。
- `boundPlan` 取代 `adoptBinding`：只读本会话绑定写进 seed 的恢复行（附「绑定未变，无需再 bind」），不再写绑定表。

配套改动：

- `src/index.ts`：`autoCheck` 参数去掉 `previousSessionId`；`inheritPlanBinding` → `boundPlan`（复用 `inheritedPlanDirectory`）；`createRotation` 不再传 `adoptBinding`/`onRotated`。
- `planning/plan-log.ts`：新增 `USER_LIMIT = 8192`，`buildTurnRecord` 的 `user` 字段改为截断写入（原来无上限，重置的 seed 会整段进 `log.jsonl`）。同时删除已无调用方的 `adoptBinding` 及其测试。
- `rotate.test.ts` 重写为遮蔽语义（20 条）：低于阈值不动、达阈值两条事件且区间/计价正确、seed 含上一轮输出块、每次产出 assistant 后允许再重置、子 agent/其他预设/steer/未知会话/回合未结束/只有系统提示时不重置、append 抛错回落、autoCheck 与 boundPlan 写进 seed。

## 验证

- `pnpm test`：43 文件 369 条全过。
- `vp check --fix`：0 error、0 warning（含类型检查）。
- `pnpm build`：通过（dist/index.mjs 212 kB、client.js 57 kB、assets 已复制）。
- `compaction/prune` 在 `dsh-session/lib/types/known-event-types.js:32` 注册，不依赖 compaction 插件是否加载。

## 已知限制

- 旧的轮转路由与客户端跟随（`toolkit-routes` 的 `rotation` 路由、`client/rotation-follow.ts`、`NanoFlowRotation` 契约）现在永远拿到 `null`，功能上无害但成了死代码；拆除会波及客户端与契约，留待单独收口。
- 遮蔽是持久的：重置后重启、fork、导出都看不到旧历史（用户已确认观感可接受）；人类可见记录仍是 append-origin 事件，GUI 照常显示。
