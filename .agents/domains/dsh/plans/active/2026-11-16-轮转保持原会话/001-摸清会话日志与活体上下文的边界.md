# 001-摸清会话日志与活体上下文的边界

## 结论：B —— 无现成「清空」API，但可在原会话内遮蔽整段历史

DSH 的会话是 **内存 append-only 事件日志 + 由表面（surface）折叠派生模型历史**。落盘只是持久化插件订阅 `session/event` 的副本。因此：

- **改 `session.v4.jsonl.zstd` 不降上下文**：活体历史来自 `session.deriveMessages()`（每次请求现算），改文件要到下次加载会话才生效。
- **删日志目录会毁活体会话**：`appendLines` 用 `open(path,"a")`，目录被删后下一条 append 会新建一个**没有 header 帧**的文件，`session.lock` 的 inode 也一起没了（等于放弃互斥）。现在 `retire()` 靠「先归档停住 → 150ms → 删」规避，原地清空后这个前提消失。
- **可行路径**：`compaction/prune`（计遮蔽价）+ 一条带 `surfaceOp:{op:"replace",startSeq,endSeq}` 的 `user/message`（新历史）。日志不删、sessionId 不变、内存会话不重建。宿主把它写成公开契约：「Used by compaction; any surface-replacing producer may use it」（`@ds/dsh-session/lib/types/types.d.ts:453-470`），`dsh-compaction-tool-result-pruner` 就是同款先例（`:159-177`）。
- **`/compact` 不是答案**：`ctx.compaction.compactNow` 是压缩（保留 ~16% 尾部 + LLM 摘要），且要求 agent idle，观感不等于清空。

## 推荐改法（交给 003）

1. **原地清空**：取 `sessions.get(id)` 的 surface 节点，保留 `nodes[0]`（系统提示），对 `nodes[1..last]` 先 `append("compaction/prune", { shadowedRange, shadowedSeqs, shadowedTokenCount })`，紧邻再 `append("user/message", {content:[seed]}, { surfaceOp:{op:"replace",startSeq,endSeq}, sourceEventSeqs })`，然后 `sessions.flush(session)`。
2. **拆掉连带动作**：不再 `archiveSession({stopActivity:true})`、`detachSession`、`recordPendingDelete`、`deleteSessionLogs`、`onRotated`。这一步本身就保住子 agent 与 job。
3. **失败回落**：prune/replace 抛错（遮蔽集不全、并发 compaction、节点已被替换）时回落到现有「新建会话」路径，否则用户这条 prompt 直接失败。
4. **触发时机**：agent 非 running 时才原地清空，否则等下一轮（`mode:'queue'` 只是排队，mid-turn 清空会与流式输出错位）。

## 对 Plan 轨迹 `log.jsonl` 的影响

- **不删、不重建**：`retire()` 只动会话日志根（`deleteSessionLogs(sessionsRoot)`），Plan 轨迹是另一条 append-only 文件，轮转从不碰它。已写下的轮次永远留着。
- **原地重置比现在更干净**：sessionId 不变 ⇒ 不触发 `planLog.forget`（`index.ts:371-377`）、不广播 `api-session/removed`、读句柄不关；去重键 `${sessionId}#${turn}`（`plan-log-service.ts:95`）不会出现「同一 Plan 下多段 sessionId、turn 号各自从 1 重数」。
- **既有脏点会延续**：`buildTurnRecord` 把所有 `user/message` 文本拼进 `user` 字段且**没有长度上限**（只有 args/result 4 KB、assistant 8 KB），所以 seed（含 ≤8 KB 的上一轮输出块 + 校验结论）与 `<rotation-prior-input>` 包装说明都会原样落进那一轮轨迹。换会话的今天同样如此，不是新问题；但原地重置后「每重置一次多一条几 KB 的 user」。建议 003 顺手处理：给 seed 内容块打来源标记让 `buildTurnRecord` 跳过，或对 `user` 字段加截断。
- **dream 游标更简单**：dream 的游标按 `(planPath, sessionId, seq)`，原地重置后同一 Plan 的 session 段更少。

## 遗留与待确认

- 客户端 transcript 不会变空：replace 只影响模型，人类可见记录仍是 append-origin 事件。产品语义需在 003 前定：显示「历史仍在 + 已重置」是否符合预期（pi 的 reset 也是过滤而非删记录）。
- `shadowedTokenCount` 算错不抛错，但会让 `contextPressure` 长期偏移，可能导致反复触发或永不触发。
- 全量清空意味着那条 replace 要列出全部被遮蔽节点的 seq，长会话下是上千元素的大事件（一次性，可接受）。
